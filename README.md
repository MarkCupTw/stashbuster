# Stash Buster（储物克星）

让普通苦力怕主动去找并炸开**玩家放置的、物品最多的储物方块**（箱子、木桶、潜影盒、漏斗……，**不含末影箱**）。

- MC 版本：**1.21.1**
- 加载器：**NeoForge 21.1.245**（`21.1.x` 均可）
- mod id：`stashbuster`
- 端：**纯服务端逻辑**。不含任何渲染 / UI / 网络包，装在服务端（或单机的内置服务端）即可生效

---

## 一、安装

1. 给游戏装上 **NeoForge 1.21.1**。
2. 把 `build/libs/stashbuster-1.0.0.jar` 丢进 `.minecraft/mods/`。
3. 启动游戏。首次启动后会生成配置文件 `config/stashbuster-common.toml`。

> 单机游玩不需要任何额外设置。专用服务器想让**没装本 mod 的客户端**也连入的话，
> 请把服务端的报错发我——NeoForge 1.21.1 已经没有 Forge 时代那个 `displayTest` 字段了
> （我在 FancyModLoader 4.0.43 的 252 个 class 里搜不到该机制），所以我不会给一个猜测的写法。

---

## 二、构建

```bash
gradlew.bat build      # Windows
./gradlew build        # Linux / macOS
```

产物在 `build/libs/`。调试运行配置：`gradlew.bat runClient` / `runServer`。

首次构建需要下载并反编译 Minecraft（视网络 10–30 分钟），之后走缓存。

## 三、配置项（`config/stashbuster-common.toml`）

### `[general]`

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关。关掉后苦力怕恢复原版行为，已记录的数据仍保留 |
| `searchRadius` | `24` | 储物方块搜索半径（格）。未加载区块里的方块读不到，会被跳过 |
| `requireNearbyPlayer` | **`true`** | 是否要求半径内有玩家才激活。**只排除旁观模式**：生存 / 创造 / 冒险都算 |
| `scoreUpdateIntervalTicks` | `20` | 重新挑选目标的最小间隔（tick），避免每 tick 重算 |
| `minimumItemCount` | `1` | 物品少于该值不作为目标。设 `0` 则空容器也炸 |

这个"玩家"**只把旁观模式排除在外**——生存、创造、冒险模式都算。
所以**创造模式下建基地时，苦力怕照样会来炸箱子**；纯旁观观察时不会。
半径与 `searchRadius` 共用（默认 24 格），也就是"**玩家 24 格内它才会主动来炸**"。

关掉它（`false`）的后果：苦力怕所在的区块只要被加载（出生点强加载、区块加载器），
哪怕没有任何玩家在线，它也会去搜刮储物方块。

### `[targets]`

| 键 | 默认 | 说明 |
|---|---|---|
| `excludedBlocks` | `["minecraft:ender_chest"]` | 不参与搜刮的方块 ID 列表，可增删 |

### `[scoring]`

| 键 | 默认 | 说明 |
|---|---|---|
| `distancePenalty` | `1.5` | 每 1 格距离扣多少分 |
| `countMode` | `TOTAL_ITEMS` | `TOTAL_ITEMS` = 堆叠数量总和；`OCCUPIED_SLOTS` = 非空格子数 |

```
score = 物品数 - distancePenalty × 距离
```

默认 `1.5` 的含义：**满箱（27 组）可以压过约 10 格的距离差**。
调大更执着于就近目标，调小更执着于物品多（调到 `0` 就完全只看物品数量、无视距离）。

## 四、哪些方块算目标

判定标准是**方块实体是否实现 `Container` 接口**，不是一份写死的方块白名单。这样自动覆盖：

- 箱子、陷阱箱、**木桶**、**潜影盒**（17 色）
- **漏斗、发射器、投掷器、合成器（Crafter）**
- **熔炉、高炉、烟熏炉、酿造台**
- **饰纹陶罐、雕纹书架、唱片机**（后两者也算 `Container`，只是可容纳 1~6 件）

以及**其它 mod 的标准容器**——只要它的方块实体按规范实现 `Container`，无需本 mod 适配。

**末影箱不参与**：它默认列在 `excludedBlocks` 里。实际上 `EnderChestBlockEntity` 压根没实现
`Container`（它的内容属于玩家个人的末影储物，并不存在于世界里），所以本来就不会被选中；
列出来是为了显式表达意图，并在将来原版改动时提供保护。

不想让某类方块被盯上（例如唱片机），往 `excludedBlocks` 里加 ID 即可，比如
`["minecraft:ender_chest", "minecraft:jukebox"]`。

## 五、行为细节

### 只认"装 mod 之后玩家新放的方块"
- 通过 `BlockEvent.EntityPlaceEvent` 记录玩家放置的坐标，写进存档（按维度分别持久化），重启不丢。
- 村庄、地牢、遗迹里原有的容器**不参与**，哪怕里面有战利品。
- 玩家自己拆掉时同步移除记录；坐标失效的条目会在下次搜索时顺手清理。

### 双重箱子
- 两个半块共享一个大箱子，按**一份**计分（不会分数翻倍），寻路只认一个坐标。
- 如果爆炸只炸到一半，只有被炸的那一半的物品会掉出，另一半保留自己的东西。

### 激活条件
苦力怕只有在自己 **24 格**（`searchRadius`）内有玩家时才主动搜刮，**旁观模式不算**。
创造、生存、冒险模式都算——所以创造模式下建基地时它照样会来。

这个条件是**持续检查的，不只在出发那一刻检查**：玩家 24 格内 → 苦力怕出发 → 玩家走远到
25 格以外 → 它会**放弃并停下**，不会继续去炸。检查与怕猫共用一次缓存，每 10 tick 刷新一次。

**唯一的例外是引信点燃之后**：一旦进入最后 1.5 秒的膨胀倒计时，就不再被任何让位条件中断
（玩家走开、猫靠近都不行）。这与原版一致——原版 `SwellGoal`(2) 优先级高于 `AvoidEntityGoal`(3)，
引信点燃后本来就不受干扰。

### 优先级：生存玩家 > 储物方块
- 苦力怕一旦**锁定**了玩家，就立刻放弃搜刮去找玩家。**容器只是没锁定玩家时的备选目标。**
- 它不会为了箱子而放弃已锁定的玩家，也不会被创造/旁观玩家"拉走"：
  原版苦力怕本来就不锁定创造与旁观（`Player#canBeSeenAsEnemy()` 对 `invulnerable` 返回 `false`），
  这两类玩家只是**让功能激活**，不会成为被追击的目标。

### 怕猫（主动让位给原版 AvoidEntityGoal）
因为本目标优先级 1 高于原版躲猫的 `AvoidEntityGoal`（优先级 3），所以必须主动让位：
水平 6 格 / 垂直 3 格内有**有视线**的猫或豹猫时，本目标的 `canUse` / `canContinueToUse`
返回 false，释放 `Goal.Flag.MOVE`，原版就能接管逃跑。检查结果按 10 tick 缓存，不会每 tick 扫猫。

判定近似原版 `AvoidEntityGoal`（原版给苦力怕注册了 `Cat`、`Ocelot` 各一条，半径 6 格，
搜索盒 `boundingBox.inflate(6.0, 3.0, 6.0)`，且 `TargetingConditions.forCombat()` 默认含视线判定）；
原版那套还要求"能找到逃跑点并成功寻路"，那部分交给原版自己负责。

### 为什么优先级必须是 1（踩过的坑，别再改回去）
本目标在主目标的第 **1** 优先级，原版针对玩家的 `SwellGoal` 在 2。这个顺序是必须的，原因已逐行核对源码：

1. `SwellGoal.canUse()` 的第一项是 `creeper.getSwellDir() > 0` —— **只要引信被点燃它就会启动**；
2. 它的 `tick()` 在没有锁定目标时执行 `setSwellDir(-1)`，把引信**掐灭**；
3. 它和本目标抢同一个 `Goal.Flag.MOVE`；
4. `WrappedGoal.canBeReplacedBy` 用的是**严格小于**：`other.priority < this.priority`。

所以只要本目标优先级 ≥ 2，点燃引信的下一 tick 就会被 `SwellGoal` 抢走 flag 并掐灭，
表现为"**苦力怕站在箱子旁边就是不爆炸**"。优先级取 1 即可压住它。

> 优先级 1 带来的"压过躲猫行为"已被上面那段主动让位逻辑解决，不再有副作用。

### 爆炸完全走原版
- 抵达目标后只做一件事：点燃原版引信（`setSwellDir(1)`）。
- 之后膨胀计时、音效、爆炸强度与范围、自爆即死**全部由原版接管**，没有自己调爆炸。
- 因此与原版不会有手感差异，也不会和别的 mod 的爆炸逻辑打架。

### 容器物品不需要本 mod 操心
需求里的"炸开容器让内容物弹出为掉落物"，**原版本来就做**，所以本 mod 一行代码都没写。
1.21.1 的实际链路（已逐行核对反编译源码）：

1. `Explosion` 对每个受影响的方块调用 `BlockState#onExplosionHit`
2. → `BlockBehaviour#onExplosionHit` → `onBlockExploded`
3. → NeoForge 的 `IBlockExtension#onBlockExploded` 默认实现：
   `level.setBlock(pos, Blocks.AIR.defaultBlockState(), 3)`
4. → `Level#setBlock` 触发 `ChestBlock#onRemove`
5. → `Containers.dropContentsOnDestroy(...)` → 内容物全部掉出

这条路径对**任何**原因导致的方块移除都生效，包括爆炸。所以：

- 苦力怕炸开容器 → 内容物照常弹出一地，不需要本 mod 介入
- 爆炸被别的 mod 取消、或 `mobGriefing=false` 导致容器没被炸掉 → 内容物**老实留在容器里**（正确行为）

我最初写过一套自己倒物品的钩子，后来**删掉了**：它和原版行为完全重复，却额外带来两个真实风险
——物品可能被倒两次（复制），以及爆炸被取消时容器已经被倒空。

### 玩家开着容器时被炸会怎样
**不丢东西、也不复制**，全由原版处理：

1. 爆炸移除容器方块
2. 原版 `ChestBlock#onRemove` 把内容物全部掉出
3. 下一 tick，`ServerPlayer` 检查 `containerMenu.stillValid(this)`；
   `Container#stillValidBlockEntity` 会校验 `level.getBlockEntity(pos) != this`，
   方块没了 → 判定失效 → 自动关掉界面
4. 关界面时 `AbstractContainerMenu#removed` 会把玩家**拿在鼠标上的那叠物品**还回背包

### 性能
- **不做任何世界范围扫描。** 只遍历"玩家放过的带方块实体的方块"这个坐标集合。
- 淘汰顺序：先算距离（纯算术，不碰世界）→ 再看区块是否加载 → 最后才读容器内容。
- 每个苦力怕有搜索冷却（默认 20 tick）和寻路重算间隔（10 tick）。
- 目标长期不可达时会放弃、临时拉黑并进入冷却，不会原地死循环。
- 集合增长只让遍历变长，与世界中方块总量无关。

## 六、设计取舍

1. **`scatterContents` / `preserveVanillaStrength` / `contentsImmuneToExplosion` 三个配置项都没实现**，
   因为原版已经提供了对应行为，做成开关只会是空开关或引入重复实现的风险。详见 §五。
2. **激活条件为 `requireNearbyPlayer`，默认 `true`，且只排除旁观模式**（生存/创造/冒险都算），
   半径与 `searchRadius` 共用。
3. **怕猫的让位逻辑是本 mod 自己实现的**——因为优先级 1 压过了原版 `AvoidEntityGoal`，必须主动让位。
4. **目标从"箱子"扩展为"所有实现了 `Container` 的方块"**，末影箱排除。

## 七、已知限制

- 不处理**实体容器**：运输矿车、箱子船、漏斗矿车。它们不是方块，没有放置事件可挂钩。
- 未加载区块内的容器读不到内容，所以实际有效范围受"区块是否加载"限制。
- 放置事件发生在方块实体创建之前，所以"带方块实体的方块"会先被记录、之后才判定是不是容器；
  非容器条目（告示牌、床、旗帜等）会在下次搜索时被清理。
- 容器被炸毁后的记录会在下次有苦力怕搜索时清理，不保证即时（一条记录 8 字节，可忽略）。
- 储物间旁边拴一只猫就能让它免于被搜刮（本目标会给躲猫行为让位）。算特性，不算 bug。
